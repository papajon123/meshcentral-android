# 0.10.1 candidate validation

Application `io.github.papajon123.meshcentral`, version `0.10.1`, code `35`. The application ID and signing identity are unchanged.

## System document picker

Biometric 1.1.0 selected Fragment 1.2.5, whose FragmentActivity rejects the request codes used by Activity Result APIs. Both real OpenDocument/CreateDocument tests reproduced the exception before the explicit Fragment 1.8.9 dependency. Both then passed, including cancellation callbacks and return to the resumed activity.

Upload selection reserves its remote folder and keeps the existing foreground service active before SAF opens. Logical cancellation releases foreground work but blocks another upload picker until the old system result is consumed. Late results do not alter unrelated operations or delete source documents. Registrations are scoped to their controller, and writes still require explicit confirmation.

The first reservation tests reproduced four failures out of seven before implementation. Independent review identified a cancelled-selection race; two additional regression cases reproduced it before the outstanding-result state was added. The final focused API 35 suite passed **71 tests without skips**, covering Agent/SFTP/Android files, source preservation, document cleanup, real system pickers and device authentication.

## Real review fixture

The Play debug client authenticated to a public HTTPS fixture containing only a synthetic Linux target. Desktop, agent-terminal and SSH input each created a marker owned by the unprivileged test user. A 45-byte Agent Files upload/download round trip matched SHA-256. An upload picker stayed open for at least 138 seconds with the foreground service active; the subsequent 40-byte upload matched SHA-256. Cancelling selection stopped the service and preserved the source.

SFTP initially failed because the fixture's OpenSSH configuration had no SFTP subsystem. After adding `Subsystem sftp internal-sftp`, real SFTP authentication and root listing passed. This fixture issue does not establish the cause of another user's SSH/SFTP report.
