## Выполнение наряда

| Пункт | Результат и доказательство |
|---|---|
| 1. Служебный `00` | Отбрасывается адаптером до разбора в p5/p10. Сокетные проверки включают его между блоками скачивания и подтверждениями отправки. Ограничение неоднозначного нулевого блока описано ниже. |
| 2. Выпущенный агент 1.0.23 | Формат определяется по первому содержательному кадру: двоичные данные без заголовка либо текст `op:ok`. Размер берётся из свежего списка, размер заголовка должен совпасть. Проверены пустой файл, JSON-подобные байты, неполный/избыточный поток и SHA-256 контрольного скачивания. |
| 3. Обрыв p5 | Отменяет p10; `catch` не отправляет через приостанавливающий `send` в закрытый канал. Есть обработчик исключений рабочего `CoroutineScope`. Сокетная и нативная проверки обрывают скачивание после первых байтов и проверяют освобождение состояния. |
| 4. Ссылка | `msg/console`, команда `openbrowser "https://example.com/"`. Требуется регистрозависимый префикс `http://` или `https://`. Буквальные пробелы и ASCII-кавычки запрещены, поскольку агент не поддерживает экранирование; `%20`/`%22` разрешены. |
| 5. Права | Сообщения, уведомления, ссылки и набор номера требуют одновременно 8 и 16, в интерфейсе и непосредственно перед отправкой. Вибрация/вспышка требуют 8. Проверены отзыв права 16 при открытом диалоге и подсказка. |
| 6. Медиа | Все одноимённые элементы сохраняются с индексом исходной строки. Агент 1.0.23 и main возвращают только `n/t/s/d`, поэтому действия для неоднозначных имён отключены с указанием открыть фактическую папку в Sdcard. Ответ медиа >1 МиБ заменяется ограниченным сообщением об ошибке с `reqid`, сохраняя p5. Сокетная фикстура содержит 16 000 строк. |
| 7. Виртуальный корень | «Отправить сюда» неактивна с подсказкой выбрать категорию. `uploadQueued` возвращает понятный отказ до открытия локального потока и не закрывает сеанс. Нативный тест проверяет повторное включение кнопки в категории. |
| 8. Служебный текст | `pong`, `ping` и сообщения `ctrlChannel:102938` не трактуются как p10-данные. Проверены pong и RTT внутри скачивания. |
| 9. Номер | Каждый `#` кодируется как `%23`, например `dial *%2306%23`; соответствует `Uri.parse("tel:...")` агента. |
| 10. Выбор документа | Подготовка, отказ подготовки и результат выбора сериализованы через mutex. Отмена, обрыв, ошибка открытия потока и отмена владельца освобождают бронь уведомления. Есть проверка гонки отключения и выбора. |
| KVM | Для WebSocket удаляется дополнение до границы 8 байт; обычный поток сохраняет склейку и фрагментацию. Проверены обычный, jumbo и фрагментированный jumbo-пакет, за которыми следует следующий пакет размера экрана. |

Дополнительно исправлено штатное закрытие p10 через ретранслятор: MeshCentral 1.3.1 вызывает
`peer.ws.close()` без кода, что OkHttp представляет как `1005`. Принимаются `1000` и `1005`,
но успешное завершение по-прежнему требует точного размера. Регрессионная фикстура посылает
настоящий пустой кадр Close (`88 00`) через TCP; до исправления она падала.

Живая отправка выявила дополнительную гонку MediaStore: сразу после `uploaddone` каталог ещё
показывал размер 0, хотя файл был полностью записан и его SHA-256 совпадал. Для уникального
медиафайла добавлены максимум пять повторных чтений метаданных с интервалом в секунду.
Передача не повторяется, несовпавший размер не принимается, проверка SHA-256 остаётся обязательной.
Нативная регрессия сначала воспроизвела отказ, затем проверены обновление размера и ограниченный
отказ при постоянно неверном размере с освобождением брони уведомления.

## Живая проверка

Агент собран из тега `1.0.23` (`527ca04`) в отдельной рабочей копии, основной клон не изменялся.
Существующий MeshCentral 1.3.1 на порту 4443 не останавливался и не перенастраивался.
Собственные эмуляторы: агент 5600, клиент 5602; `Medium_Tablet`, `-read-only -no-snapshot
-no-window -no-audio -no-boot-anim`. Агент — 1536 МиБ/два ядра; первоначальный клиент — также
1536 МиБ/два ядра. Окончательный клиент — 3072 МиБ/четыре ядра в отдельной временной копии
конфигурации того же AVD: общий каталог при перезапуске возвращал QEMU `Permission denied`.
Исходная конфигурация не редактировалась. Перед каждым запуском было больше 6 ГиБ
свободной физической памяти. Чужие эмуляторы не использовались.

- Скачивание PNG 99 байт через исходный адрес стенда прошло; содержимое проверено SHA-256.

- Первая длительная отправка с ограничением 64 КиБ/с пережила 165 секунд, файл был записан
  с правильным SHA-256. Контрольное чтение не началось из-за описанной гонки размера MediaStore.
- После исправления MediaStore окончательная отправка `phone-final.png` запущена через настоящую

### Особенность сети эмулятора

При обращении клиента через `10.0.2.2` скачивание 8 МиБ воспроизводимо обрывалось в Android
Conscrypt с `BAD_DECRYPT/DECRYPTION_FAILED_OR_BAD_RECORD_MAC` до последних 1–2 блоков.
Та же передача через Node, включая замедленное чтение, возвращала все 129 блоков и верный хеш.
После изменения только пути клиента на `adb reverse` и `https://127.0.0.1:4443/` тот же APK
получил весь файл и штатное закрытие `1005`. Это подтверждает зависимость от сетевого пути
эмулятора; точный дефект его реализации здесь не устанавливался. Похожая потеря TCP-байтов
описана в [Android Issue Tracker](https://issuetracker.google.com/issues/150758736).

Окончательная сборка с обновлённого main использует явное `Trust this server` и привязку ключа.
Показанный SPKI независимо сверен с локальным публичным сертификатом действующего стенда;
debug-обход TLS при окончательной проверке не включался.

Живая приёмка завершена перед заключительным перебазированием, как предусмотрено нарядом. Сравнение
исходников с проверенной версией `e0a28e3` подтвердило тождественность адаптера/контроллера файлов,
файлового транспорта, команд телефона, экрана файлов, панели отправки и KVM-декодера.
Параллельные изменения авторизации и управления телефоном из main проверены полным автоматическим
набором. Их отдельная живая приёмка в этот наряд не входила.

Для проверки длительности используется собственный прозрачный TCP-ограничитель на loopback,
не изменяющий TLS и содержимое: агент — ADB reverse — порт 4445 — существующий сервер 4443.
Клиент подключён к тому же серверу через ADB reverse напрямую. Временные диагностические
сообщения полностью удалены; послаблений проверки размера, хеша или TLS в код не внесено.

## Решения и пределы доказательств

В наряде требуется считать отдельный `00` служебным также в p10. Однако таймер обеих версий
агента исключает usage 10, поэтому в настоящем p10 этот кадр может быть единственным нулевым
байтом файла или его последнего блока. Буквальное требование выполнено: такой кадр отбрасывается,
после чего проверка размера отклоняет файл. Восстановления байтов по заявленному размеру нет.
Это ограничение документировано и закреплено отдельным тестом безопасного отказа.

Независимое рассмотрение первоначального набора Astra нашло один существенный дефект обработки
`1005`; он исправлен и проверен сокетной регрессией. Гонки MediaStore, подготовки тестов и
освобождения TLS-пула дополнительно выявлены во время приёмки и проверены регрессиями.
Физические телефоны, реальный агент main, выполнение звонка/ссылки на физическом устройстве
не проверялись. Публикаций, push и MR нет; решение о дальнейшей интеграции остаётся ведущему.

Удаление созданных временных каталогов `live/avd-home` и `live/client-avd-data` запрещено
автоматической проверкой инструмента (`blocked by policy`). Они оставлены; обходов запрета нет.
Существующий сервер и чужие эмуляторы не останавливались. Собственные эмуляторы и TCP-ограничитель
остановлены после завершения проверок. Порт действующего стенда 4443 продолжает слушать.
